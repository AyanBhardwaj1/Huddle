# A6 Announcer: status

Owner: workstream A6. Code: `packages/announcer/`. Last updated: 2026-11-16.

No API keys were available while building this. Everything below marked "verified" was verified with
unit tests, a local HTTP stand-in for the two APIs, or by running the scripts without keys. Nothing has
been run against the real ElevenLabs or Anthropic services yet: see "Not verified without keys".

## What the engine imports

```ts
import { createLlmClient, createAnnouncer } from '@huddle/announcer';

const llm = createLlmClient(process.env);            // LlmClient
const announcer = createAnnouncer(process.env, llm); // Announcer (with agentSession)
```

Names and signatures are unchanged from the stub. Both take an optional last argument
(`{ fetch, log, now }`) used by tests; the engine does not need it.

| Call | Behaviour |
| --- | --- |
| `announcer.warmup(persona)` | Remembers the persona and pre-generates 18 common lines ("Five seconds! Last call!", "Locked!", "Last call!", void lines). No-op with one warning when there is no ElevenLabs key. Never throws |
| `announcer.announce(event, ctx)` | Returns an `AnnouncerLine` (or `null` when there is nothing worth saying). Never rejects. `audioUrl` is `/audio/<id>` when a clip is ready inside the budget, otherwise absent |
| `announcer.getAudio(id)` | `{ mime: 'audio/mpeg', data }` for a clip id or `sfx-<name>`; `undefined` otherwise. Synchronous. Survives restarts (disk cache) |
| `announcer.answer(text, talkContext)` | Rule-based TALK reply, with `draft` for bets. Never throws |
| `announcer.agentSession({ partyCode, playerName, sessionToken })` | `{ agentId, signedUrl, dynamicVariables }` or `null` |
| `announcer.provider` | `'elevenlabs'` while speech synthesis works, `'webspeech'` with no key or during an outage |
| `announcer.lastWarning` | (extra, on `HuddleAnnouncer`) the last warning text, for the host screen |

## Not verified without keys

Each of these is implemented from the official docs and tested against mocks only.

1. **Real ElevenLabs TTS call.** Endpoint, header, query and body were checked against the API reference
   on 2026-11-16, but no real request has been made. Unknowns: whether `eleven_flash_v2_5` accepts every
   field in our `voice_settings` on the account's plan, and real latency.
2. **The 2.5 s latency target.** Measured only against a local server. With the real services the worst
   case is LLM 1.5 s (timeout) plus TTS; lines that miss 2.2 s go out as text for Web Speech.
3. **Default voice ids.** Only George (`JBFqnCBsd6RMkjVDRZzb`) is confirmed by the official quickstart.
   `cjVigY5qzO86Huf0OWal` (Calm) is the Agents API's documented default voice id; the name "Eric" is from
   memory. `nPczCjzI2devNBz1zQrb` ("Brian", NFL) is from memory and was not found in the docs. If either is
   rejected the announcer falls back to George for that persona and logs one warning.
4. **Real Anthropic call.** Request shape follows the bundled Claude API reference (`anthropic-version:
   2026-10-21`, no sampling parameters, thinking disabled, effort low). Not run against the API. Line quality
   from `claude-haiku-5-5` and how often it passes validation are unknown.
5. **Sound Effects generation.** `scripts/generate-sfx.ts` has not produced real files; `assets/sfx/` is
   empty, so lines carry `sfx` without `sfxUrl` and clients must synthesize a cue.
6. **Agents API.** `setup-agent.ts` has not created a real agent. The create-agent and create-tool body
   shapes come from the API reference; the dashboard steps in `AGENT_SETUP.md` describe settings, and the
   exact menu labels were not checked against the live dashboard.
7. **Signed URL with dynamic variables in the client SDK.** `Conversation.startSession({ signedUrl,
   dynamicVariables })` is documented, but the client side belongs to A4/A5 and is untested here.

- Clients (A4/A5): play `sfxUrl` before the line when present, synthesize a cue from `sfx` when it is
  absent, and speak `text` with Web Speech when `audioUrl` is absent.
- Not built: streaming audio bytes to clients while the clip is still being generated. Clips are cached
  whole and served at `/audio/:id`; a short line is a few hundred milliseconds of generation, so this was
  not worth the protocol change.
- Not built: the disk cache has no size limit or eviction (the memory cache holds 400 clips).

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| A6-1 | Default `LLM_MODEL` is `claude-haiku-5-5`, sent with thinking disabled and effort `low` | The announcer has 1.5 s; the Haiku tier is the fast one, and thinking only adds latency for a two-line reply |
| A6-2 | `anthropic-version: 2026-10-21`, plain `fetch`, no sampling parameters | The task allows `fetch`; that API version rejects `temperature`, so none is sent |
| A6-3 | Default TTS model `eleven_flash_v2_5` (override: `ELEVENLABS_TTS_MODEL`) | Documented at about 100 ms and long established. The docs also recommend the newer `eleven_v4_turbo` for low latency; switch with the env var after listening |
| A6-4 | Captions keep "$8" and "77%"; the text sent to TTS is rewritten locally to "8 dollars", "77 percent" | The low-latency models skip text normalisation by default; doing it ourselves works on every model and plan |
| A6-5 | Whole amounts are spoken without ".00" ("$8", "8 pts"), still produced by `formatUsd` | "Eight dollars" reads and sounds better than "eight dollars zero zero" |
| A6-6 | One deadline per line from the moment of the event: 2.2 s for high priority, 0.8 s for countdown lines, 4 s for low and medium | Late audio is worse than browser speech; countdown lines are worthless late; low-priority lines are dropped by the queue at 6 s anyway |
| A6-7 | A line that misses its budget still finishes generating in the background | The clip is ready for the next time the same line is needed |
| A6-8 | An ElevenLabs error puts TTS in a 30 s cooldown (10 s for 429, permanent for 401/403) with one warning per outage | "Log one warning", and do not hammer a failing API during a live game |
| A6-9 | A rejected persona voice falls back to the default voice for that persona only | Two of the three default ids could not be confirmed in the docs; a wrong one must not silence the room |
| A6-10 | LLM lines must contain the key fact (for example the favourite's percentage or the result) and no number outside the facts, in digits or words; a lone "one" is not treated as a number | Stops the model dropping or inventing the news; "that one is off" must not trip the check |
| A6-11 | Templates are chosen by an FNV hash of the event's own identity (market id, fill id, names) | Deterministic for tests and replays, varied across a game |
| A6-12 | Stinger choice for a resolved market: nobody won = sad trombone; a goal or touchdown = goal horn (soccer) or crowd roar (NFL); one big loss (5 USDC or more, larger than any win) = sad trombone; otherwise a payout = cash register | One stinger per line; the moment itself outranks the money |
| A6-13 | TALK picks the market that explains the most words after "on"; ties go to a named outcome, then keywords, then the newest open moment market | "Five on Portugal" is the match winner; "five on Portugal reaching seven corners" is the corners market |
| A6-14 | "Ten on Ronaldo scoring" with no side named drafts Yes on the matching yes/no market ("to miss", "won't" draft No) | Natural speech rarely says "yes"; the reply states the side and nothing happens until the player confirms |
| A6-15 | The optional LLM pass on TALK replies is rejected unless every number survives unchanged and the "confirm" instruction is kept; the draft is never passed to the LLM | Phrasing only; the voice path must not alter amounts |
| A6-16 | `agentSession` returns `null` when the signed URL cannot be fetched | The agent is private (auth on); without a signed URL the client could not connect, so fall back to offline TALK |
| A6-17 | The box (no player name) passes `player_name = "the room"` and the prompt makes the agent ask who is speaking before drafting | A missing dynamic variable fails the conversation start |
| A6-18 | The agent's first message is empty | Push-to-talk: the player speaks first |
| A6-19 | The agent's TTS model and LLM are left at the platform defaults unless `ELEVENLABS_AGENT_TTS_MODEL` / `ELEVENLABS_AGENT_LLM` are set | The docs did not state the LLM default or which TTS models an English agent accepts |
| A6-20 | The tools' secret header is sent as a constant string in the tool config | The docs do not describe how to create a workspace secret by API; the dashboard guide suggests storing it as a secret by hand |

## Needs a human

1. Put `ELEVENLABS_API_KEY` and `ANTHROPIC_API_KEY` in `.env`, then run
   `pnpm --filter @huddle/announcer demo-lines`. Check: lines report `audio=miss /audio/...` (countdown lines
   `audio=hit` after the warmup), the summary shows no line over 2.5 s, and there is no `!` warning about a
   rejected voice or a failed request. Run it again with `ANNOUNCER_LLM_LINES=0`: every line should now be
   `audio=hit`, served from the disk cache.
2. Listen to a few clips in `data/audio-cache/` for each persona. Check that "$8" and "77%" are read as
   "eight dollars" and "seventy-seven percent", and that the three voices suit the personas. Change voices
   with `ELEVENLABS_VOICE_SOCCER` / `_NFL` / `_CALM` (stock library voices only, no clones).

   but pick library voices explicitly if this lives longer.
4. Read ten LLM lines for tone. If many fall back (`LLM line rejected (...)` in the log), paste the reasons
   to A6; the prompt or the validator needs tuning.
5. Run `pnpm --filter @huddle/announcer sfx`, listen to the five files in `packages/announcer/assets/sfx/`,
   regenerate any bad one with `-- --force`, and commit them.

7. Decide whether TALK should follow the persona: if yes, create three agents and set

## ElevenLabs products used, and how (for the README)

| Product | How Huddle uses it |
| --- | --- |
| **Text to Speech** | Every announcer callout. Streaming endpoint (`POST /v1/text-to-speech/{voice_id}/stream`, `output_format=mp3_44100_128`) with the low-latency model `eleven_flash_v2_5` and one stock library voice per persona (Soccer, NFL, Calm), each with its own voice settings. Clips are cached by hash(voice + model + settings + text) in memory and on disk; the common countdown lines are pre-generated at party start so they play instantly. Lines that cannot be voiced inside the latency budget are spoken by the browser instead |
| **ElevenLabs Agents** | The TALK button and the app's mic button. A private agent with the persona voice and a Huddle system prompt; the engine issues a signed conversation URL per session and passes `party_code`, `player_name` and `session_token` as dynamic variables. Four server tools (webhooks to the engine, authenticated with a shared secret header): `get_party_state`, `get_market`, `explain_odds` and `draft_bet`. All are read-only except `draft_bet`, which only creates a draft the player confirms in the app; the agent can never move money |
| **Sound Effects** | Five stingers generated once at build time with `POST /v1/sound-generation` and cached in the repo: goal horn, touchdown crowd roar, lock buzzer, cash register (payout) and sad trombone (big loss). The announcer attaches the right one to each line and the box plays it before the voice |

No voice is cloned and no real commentator or celebrity is imitated: the prompts forbid it and LLM lines
that name one are rejected.
