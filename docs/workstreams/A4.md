# A4 Player app (`apps/player`)

Phone PWA every player uses. React 18 + Vite 5 + Tailwind 3 (shared preset) + zustand + framer-motion. Everything engine-facing goes through `HuddleClient` from `@huddle/shared`.

## Run it

- `pnpm --filter @huddle/player dev` (port 5173, proxies `/ws /parties /games /faucet /audio /agent /health` to `http://localhost:8080`; `VITE_ENGINE_URL` overrides the engine base).
- **No engine needed for review:** `http://localhost:5173/?fixture=1` (live screen), `?fixture=buyin`, `?fixture=end`. Fixture data and its fake client live in `src/fixture.ts` only.
- Join links: `/j/CODE` (in-room), `/j/CODE?r=1` (remote: speaker on by default, sync check shown).
- Icons: `node apps/player/scripts/gen-icons.mjs` regenerates the PNGs from the same design as `public/icon.svg`.

## Unverified against a real engine

The engine is being built in parallel, so none of this has run against it yet:

- REST shapes: `GET /parties`, `GET /parties/:code` (404 -> "Party not found"), `POST /faucet`, `GET /agent/session` (`{ agent: null }` -> fallback).
- Ack data of `buy_in` in vault mode (handled entirely inside `HuddleClient.buyIn`).
- Whether the engine sends `leaderboard` after a buy-in; the app does not depend on it (a local flag moves past the buy-in screen).
- Whether resolved markets keep the player's positions or emit `payout`/`refund` fills; `marketResult` uses fills first, then positions.
- `sync_mark.clientTs` is sent in engine time (`client.now()`), not raw `Date.now()`.
- Announcer `audioUrl` paths are resolved against the engine base (works for `/audio/...`).
- ElevenLabs agent path (needs a real agent + mic permission); Web Speech recognition on iOS Safari; actual install on iOS/Android; how it looks (no browser tools were used; the orchestrator will review visually, ideally via `?fixture=1`).

## Left / ideas

- Withdraw to an external wallet (P1) and "Back up" (P2) are not built.
- No "change name" link on the join screen for returning players.
- Bundle: main chunk ~500 kB (shared zod/decimal/tweetnacl); ElevenLabs is a separate lazy chunk (~660 kB) but is precached by the service worker.

## Decisions

| # | Decision | Why |
| --- | --- | --- |
| A4-1 | Stake chips place the bet on tap (no extra confirm); the chip shows the payout before you tap. | "One tap" from PRD; the preview removes the need for a confirm step. |
| A4-2 | Chips are $1/$2/$5 under the cap plus "max" = `floor(balance x maxStakeFraction)`. | Matches the engine's per-market stake limit so "max" never hits `stake_limit`. |
| A4-3 | `cosign_required` is retried once after 1.2 s before showing an error. | D6 makes a just-arrived state block bets for a moment; honest players should never see it. |
| A4-4 | One-tap "Back" in bet mode shows a friend's offer odds only when they beat the model odds. | Mirrors D10 (match best opposite offers first) without promising odds the engine won't give. |
| A4-5 | Returning players (name stored) auto-join on `/j/CODE`; first-timers type a name and can tick "watching from somewhere else". | Fastest path for the 30-second join; remote can still be chosen without an `?r=1` link. |
| A4-6 | The buy-in screen can be skipped ("Just watch for now"); the balance pill opens top-up later. | Lets a judge look before paying in; never a dead end. |
| A4-7 | The house account is hidden from the leaderboard. | It is the market maker, not a player. |
| A4-8 | Captions sit above the tab bar, left of the mic, and auto-expire after 7 s. | Visible but never over the score or the stake chips. |
| A4-9 | Friends vs. the Pros shows on binary markets and any market with a Gemini ref, for the Gemini outcome (else the first outcome). | "Every comparable market"; categorical markets without a Gemini price have nothing to compare. |
| A4-10 | Tiny dependency-free icon generator script instead of an image toolchain. | Keeps the install small; icons are simple shapes. |

## Shared changes requested

- `HuddleClient` refuses (mismatch prompt) the first state after a player loses IndexedDB mid-party (nonce gap from 0). Suggest: when there is no `lastSigned`, accept the engine's last fully countersigned state (`memberSig` present and verifiable) as the base.
- `HuddleClient` has no way to know which fills/positions belong to settled markets; a per-player `result` (won/lost amount) on `market_upsert` or a `payout` fill per market would make the result badge exact instead of estimated.
